### Context on arrival

Victor supplied two ZIPs — a Vex-prepared support-page handoff packet
(content canon, payment-route state, capacity figures, review checklist) and
the Vextreme Design Foundation (tokens, logo, component library, two UI kits) —
plus five tier images, and asked for a "financial landings page." He also asked
for something the request only reveals on a second read: he had **lost
traceability** on where the page that describes what Vextreme is actually
lived, and wanted it named `vextreme-home` so he could find it again.

It did not exist. `pages/` holds 39 files and every one of them is an archive
record. The only artifact that had ever described Vextreme in the Design
Foundation's voice was `ui_kits/covenant/index.html` **inside the ZIP** — a
React specimen that was never landed in this repository. That is the whole
traceability loss: not a misplaced file, an unbuilt one.

Three facts checked against GitHub rather than assumed, because the whole
design depends on them: **Vextreme is public with Pages enabled; Vextreme-SDK
is private; VexLife is private.** A public page linking to VexLife would render
a 404 for every logged-out visitor.

### Decisions

**A second kind of page now exists.** Victor's own framing — *"it's like not
contents for the institution, but it's part of the institution"* — is a real
boundary, so it got a real one. Institutional surfaces carry a `vex-` /
`vextreme-` slug prefix, take no `nodes.json` entry and no arc, use the
`institution` string scope rather than `pages.{slug}`, and are self-contained
rather than God-Script-assembled. Full rationale and the opt-out table live in
`docs/architecture/18-institutional-pages.md`.

The non-obvious mechanic: the **string scope choice is what prevents a dead
God Script.** `lib/build-vextreme.js` assembles for any slug in `index.slugMap`
whose default `pages.{slug}` bundle exists. A `SKIP_PAGES` entry alone does not
stop it. Scoping the strings to `institution` means that bundle never exists,
so the assembler skips both pages on its own.

**The Design Foundation landed as a third token family in
`styles/design-system.css`, not as a per-page `:root`.** Two pages
hand-copying one token block is exactly the drift td-007 already closed for the
four dashboard files. The one trap worth carrying forward: `foundation` and
`foundation-light` are mutually exclusive attribute values, so the shared
declaration block must match **both** selectors and let light override only the
ramp — matching just `[data-theme="foundation"]` leaves every semantic token
undefined in light mode. `check-design-tokens.js` needed no logic change;
`extractRootTokens()` already reads declarations under any selector.

**What is deliberately withheld, and why it is written down.** The handoff
supplied real capacity figures. One ($14,737.27) was tied to March 1 2026 — a
date already five months past when the packet was written. One ($398,509.42)
has ambiguous component scope that risks double-counting. Publishing either as
a balance would be the precise failure this institution exists to make visible,
so the capacity ladder carries **stage state, not amounts**. The figures and
the reason for withholding them are recorded in `data/support-routes.json`
under `capacityFigures`, so the next instance finds the decision rather than
re-deriving it and guessing differently.

**What Victor did authorize.** The tier amounts ($7/$33/$77/$333) render with
no destination attached — his explicit instruction, recorded at
`tierAmounts.confirmedBy`. This overrides the packet's own
`LEGACY_VALUES_PENDING_VICTOR_CONFIRMATION` gate, because Victor is the source
of that gate.

**Zelle is named as the open route but publishes no handle.** Victor said it is
his only current income route; he did not supply the detail, and this
repository must not reconstruct one. Route state lives in
`data/support-routes.json`; a route with a `null` url has no code path that
renders a button. `candidateUrl` is a deliberately different field name from
`url` so a URL recorded for verification cannot render by accident.

**The founder testimony is en-only on purpose.** Everything else on both pages
carries en/ja/zh. The canon supplies that passage as *"Spoken by Victor,
written by Vex"*, and the institution's standing rule is that a translation is
an attributed projection, never a replacement. An unreviewed machine
translation under that byline would break the exact rule the page explains. The
existing missing-key fallback renders English in place, and
`institution.common.label.translation-pending` states it where a reader sees it.

### Two bugs the render caught that reading the code did not

Both were found by looking at the first screenshot, which is the argument
`docs/architecture/11-debugging-practices.md` makes, landing again:

1. **`.vex-section` and `.vex-header-inner` share an element with
   `.vex-inst-shell` and are declared after it**, so `padding: X 0` silently
   zeroed the shell's horizontal padding. Invisible at 1440px (the max-width
   leaves margins anyway) and flush against the viewport edge at 320px. Fixed
   with `padding-block`. Worth generalizing: any utility class that sets a
   padding *shorthand* while sharing an element with a layout class is this bug
   waiting to happen.
2. **A `fullPage` screenshot does not trigger `loading="lazy"` images.** The
   support imagery rendered as empty grey frames — a harness bug that reads
   convincingly as a layout bug. `scripts/screenshot-institutional.js` now
   scrolls the page through and awaits every image before shooting.

### Boundaries

- No payment destination is published. No route is live. Nothing on either page
  can send a visitor to an unverified financial endpoint.
- No financial figure is published beyond the tier amounts Victor confirmed.
- No link to VexLife or Vextreme-SDK. Both repositories are private; the
  VexLife card on the home page is deliberately not an `<a>`.
- Vextreme-SDK is acknowledged in the lineage and explicitly named as not
  exposed, not linked, and not purchasable at any support level.
- No analytics, no third-party checkout, no client secrets, no form submission.
- Nothing was changed in the Vextreme-SDK repository by this session.
